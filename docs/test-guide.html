BFL platform — test guide

Follows the real lifecycle: create season → applications open → registration closes & admin reviews → confirm and choose team formation → teams form → the rest. Everything runs on your laptop against the dev database (a copy of production) — nothing here touches the live site.

Start from the beginning: in a terminal in football-tournament/ run npm run demo:down then npm run demo:up. That builds “BFL Season X (demo)” exactly as a brand-new season looks: applications open, team formation not chosen, no teams, 22 applications waiting (spread over current batches in semesters 2–7, plus three alumni batches). Server: localhost:3100. Admin login: /admin/login with your usual account. Use a private window for “player” steps. If the server was started before an update, restart it (Ctrl-C in its terminal tab, then npm run dev -- -p 3100).

How a batch becomes a semester

A batch is named by the term it graduates: “Fall 27” = the batch graduating in Fall 2027. Terms follow the campus calendar — Spring = April–August, Fall = September–March. A batch is in its 8th (last) semester in the term it graduates, so counting back from the graduation term gives its current semester. Once that term has passed, the batch is alumni. A batch that graduates 8 or more terms from now hasn't started yet and is refused.
